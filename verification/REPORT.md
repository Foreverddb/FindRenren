## 抠图方案

| 方案 | 许可证 | 结论 |
| --- | --- | --- |
| `@imgly/background-removal` | AGPL-3.0 | 浏览器端能力完整，但许可证约束较强，未采用 |
| `Transformers.js 4.2` + `Xenova/MODNet` | Apache-2.0 | 256 × 256、q8 量化、6,632,188 bytes，作为“低”质量快速方案 |
| `Transformers.js 4.2` + `onnx-community/BEN2-ONNX` | MIT | 1024 × 1024、FP16、219,121,675 bytes，作为“高”质量精细方案 |

- 部署方式：两套权重与配置均位于当前站点基址下的 `models/`，不请求外部模型服务
- 加载方式：编辑器完成首屏渲染后，两套模型在浏览器空闲时同时静默预载，不阻塞调色和文字编辑
- 等待反馈：仅当用户点击当前质量且对应模型尚未就绪时显示确定进度条，按累计字节实时显示“已下载 / 总大小 + 百分比”，下载完成后自动开始抠图
- 进度总量：不依赖 CDN 是否返回可靠 `Content-Length`，使用本地校验清单中的 219,121,675 bytes 与 6,632,188 bytes 作为稳定总大小
- 下载超时：不设置；慢速网络下保持原下载任务和实时进度，直到完整下载或发生明确网络错误
- 结果缓存：每张上传图片分别缓存高、低质量透明结果，切换质量或完整/抠图模式不重复推理
- 推理方式：单线程 WASM，本地运行，失败时自动回退到完整图片模式
- 第三方来源和许可证记录见 `THIRD_PARTY_NOTICES.md`
